# Depth Region VLM 실험

VLM 비전 인코더 안에서 시각 토큰을 합칠 때 **깊이(depth) 영역 정보**를 쓰면 정확도를 덜 잃는지 비교한 실험입니다. 실험 조건은 추론 전에 protocol([7B](experiments/2026-10-28_7b_vqav2_gqa/protocol.json), [0.5B](experiments/2026-10-28_0.5b_vqav2_gqa/protocol.json))에 고정했고, 결과를 본 뒤 바꾸지 않았습니다. 같은 모델로 ToSA의 병합량과 양자화의 관계도 따로 실험했습니다.

## 요약

같은 문항끼리 비교한 95% 신뢰구간(paired bootstrap)으로 판단했습니다. 두 모델에서 경향이 같습니다. 병합이 적을 때는 Depth 방법이 ToSA보다 높고, 병합이 많아지면 ToSA가 앞섭니다.

### LLaVA-OneVision-7B

- **VQAv2 counting, 156개·338개 병합:** Depth-only와 Depth-RGB가 ToSA보다 높습니다. 156개 병합에서는 VQA accuracy가 9~10%p 높습니다(신뢰구간 +6.7~+12.9%p). 338개 병합에서는 3~4%p 높습니다(Depth-RGB +3.21%p [+0.37, +6.19], Depth-only +4.22%p [+1.31, +7.26]).
- **VQAv2 counting, 520개·650개 병합:** ToSA가 가장 높습니다. 520개 병합에서 Depth-RGB는 ToSA보다 3.77%p 낮습니다 [−6.77, −0.73]. Depth-only와 ToSA의 차이(−2.49%p [−5.47, +0.52])는 불확실합니다. 650개 병합에서는 Depth 방법이 55%의 문항에서 실행 불가가 되어 30%p 넘게 낮습니다.
- **GQA:** 156개 병합에서만 Depth-only가 ToSA보다 0.65%p 높습니다 [+0.13, +1.18]. Depth-RGB와 ToSA의 차이(+0.44%p [−0.07, +0.96])는 불확실합니다. 338개 병합에서는 모든 방법의 차이가 불확실합니다. 520개 병합부터는 Depth 방법이 낮습니다.
- **ToSA와 ToMe:** VQAv2 counting에서는 모든 병합 강도에서 ToSA가 4~8%p 높습니다. GQA에서는 모든 병합 강도에서 차이가 불확실합니다.

### LLaVA-OneVision-0.5B

- **VQAv2 counting, 156개·338개 병합:** Depth-only와 Depth-RGB가 ToSA보다 높습니다. 156개 병합에서는 VQA accuracy가 8.1~8.4%p 높습니다(신뢰구간 +5.3~+11.3%p). 338개 병합에서는 5~7%p 높습니다(Depth-RGB +5.33%p [+2.26, +8.40], Depth-only +6.50%p [+3.62, +9.40]).
- **VQAv2 counting, 520개·650개 병합:** ToSA가 가장 높습니다. 520개 병합에서 Depth 방법과 ToSA의 차이는 불확실합니다(Depth-RGB −2.45%p [−5.28, +0.47], Depth-only −2.82%p [−5.84, +0.21]). 650개 병합에서는 Depth 방법이 55%의 문항에서 실행 불가가 되어 약 30%p 낮습니다.
- **GQA:** 156개 병합에서 Depth-only(+1.64%p [+1.11, +2.17])와 Depth-RGB(+1.48%p [+0.94, +2.04]) 모두 ToSA보다 높습니다. 338개 병합에서는 Depth 방법과 ToSA의 차이가 불확실합니다. 520개 병합부터는 Depth 방법이 낮습니다.
- **ToSA와 ToMe:** VQAv2 counting에서는 156~520개 병합에서 ToSA가 4.6~6.3%p 높고, 650개 병합에서는 차이가 불확실합니다(+0.81%p [−1.29, +2.90]). GQA에서는 338개 병합에서만 ToSA가 0.52%p 높고 [+0.03, +1.03], 나머지는 불확실합니다.

### ToSA 병합량과 양자화

- 병합량(0~650개)에 따라 양자화 손실이 달라진다는 근거는 찾지 못했습니다. 미리 정한 주 검정 32개 가운데 31개가 차이 불확실이고, 나머지 1개도 실행마다 달라지는 값입니다. 자세한 내용은 [아래](#tosa-병합량과-양자화-1)에 있습니다.

## ToSA 병합량과 양자화

**가설:** ToSA로 시각 토큰을 많이 병합할수록 양자화로 잃는 정확도가 커진다. 조건은 추론 전에 [protocol](experiments/2026-10-28_tosa_quantization/protocol.json)에 고정했습니다.

그래프: [`figures/quantization/`](figures/quantization) (모델·벤치마크마다 왼쪽은 점수, 오른쪽은 양자화 손실과 95% 신뢰구간)

### 결론

미리 정한 주 검정 32개 가운데 31개에서 신뢰구간이 0을 포함합니다(차이 불확실). 남은 1개(7B, 비전 W8A8, VQAv2 counting, 338개 병합)도 가설과 반대 방향이고, 실행마다 달라지는 값입니다(아래 반복 실행). **병합량에 따라 양자화 손실이 달라진다는 근거는 찾지 못했습니다.**

- 병합량과 관계없이 양자화 손실이 뚜렷한 조건은 0.5B의 LLM W4A16입니다. VQAv2 counting에서 병합하지 않아도 6.46%p를 잃고 [−9.12, −3.89], 338개 병합에서도 6.41%p를 잃습니다 [−8.97, −3.84].
- 7B의 LLM W4A16은 GQA 650개 병합에서 손실이 1.90%p 더 커지지만 [−3.85, +0.00], 구간이 0에 닿아 차이 불확실입니다.
- 검정 32개를 다중비교 보정 없이 읽었습니다. 보정하면 유의한 결과는 더 줄어듭니다.

### 설계

| 항목 | 내용 |
|---|---|
| 모델 | LLaVA-OneVision-7B, LLaVA-OneVision-0.5B (위 실험과 같은 실행 경로) |
| 방법 | ToSA만 사용 |
| 병합량 | 층마다 `r` = 0, 3, 6, 9, 13, 16, 20, 23, 25개 → 729개 중 0~650개 병합 (9단계) |
| 정밀도 | FP(위 실험과 같은 FP16/BF16), 비전 인코더만 W8A8 또는 W4A16, LLM만 W8A8 또는 W4A16 |
| 벤치마크 | VQAv2 counting 1,000문항(위 실험과 같음), GQA testdev-balanced 2,000문항 (`datasets/gqa_testdev_balanced_2000.json`, seed 20261028로 뽑음) |
| 주 검정 | `I = Q(r) − Q(0)`, `Q(r) = 양자화 점수 − FP 점수`. 338개·650개 병합에서 같은 문항끼리 bootstrap 10,000회, 95% 구간. 구간이 모두 0보다 작으면 가설을 지지합니다. |

- **W8A8:** 가중치는 출력 채널별 8-bit, 활성값은 토큰별 동적 8-bit입니다.
- **W4A16:** 가중치만 입력 채널 128개 묶음별 4-bit입니다.
- 양자화는 시뮬레이션(fake quantization)입니다. 값을 반올림해 원래 자료형에 저장하므로 속도와 메모리는 그대로입니다.
- 대상은 비전 인코더 26개 층의 Linear 156개, 또는 LLM decoder 층의 Linear(0.5B 168개, 7B 196개)입니다. projector, lm_head, 정규화 층은 양자화하지 않았습니다. calibration 데이터는 쓰지 않았습니다.

## 방법

다섯 방법 모두 ToSA 공식 코드의 같은 ToMe 블록을 거칩니다. 비전 인코더의 26개 층마다 `r`개씩 토큰을 합치며, `r = int((384·384/14²)·(1 − keep)/27)`는 공식 코드의 식을 그대로 썼습니다. 병합한 토큰은 복원하지 않고 LLM에 넘깁니다.

| 방법 | 어떤 토큰을 합치는가 |
|---|---|
| Token merge 없음 | 합치지 않음. 같은 계산 경로에 `r = 0`을 넣었습니다. |
| ToMe | 공식 ToMe. attention key가 비슷한 토큰끼리 합칩니다. |
| ToSA | 공식 ToSA. key 유사도에 깊이와 위치를 섞으며, 깊이 비중은 층마다 커집니다. |
| Depth-only | 깊이 영역과 위치가 비슷한 토큰끼리, 같은 연결 영역 안에서만 합칩니다. 경계 토큰은 보호합니다. |
| Depth-RGB | Depth-only와 같은 제약에서, 깊이·위치 점수와 key 유사도를 0.5씩 섞어 합칩니다. |

- Depth-only도 VLM에는 RGB 이미지를 그대로 넣습니다. 이름은 병합 기준만 뜻합니다.
- 깊이는 Depth Anything V2 Small로 미리 만들었습니다.
- 답변은 greedy decoding으로 생성했습니다. prompt는 공식 `run_vqa_3d_tome.py`의 것을 그대로 썼습니다.

```bash
for m in 7b 0.5b; do
  R=results/2026-10-28_${m}_vqav2_gqa
  python scripts/summarize.py $R        # 채점과 CSV 생성 (bootstrap 때문에 메모리가 넉넉해야 합니다)
  python scripts/feasible_subset.py $R
  python scripts/readme_tables.py $R    # README 결과 표 출력

python scripts/summarize_quant.py results/2026-10-28_tosa_quantization
python scripts/plot_quant.py results/2026-10-28_tosa_quantization figures/quantization
python -m pytest scripts/test_counting_rca.py
```

추론은 PBS job 안에서 `scripts/launch_eval.sh JOB RUNTIME DATA EXPERIMENT OUTPUT dataset:variant:shard:num_shards:gpu ...`로 실행했습니다. `EXPERIMENT`는 `experiments/` 아래 폴더 이름이고, 모델은 그 protocol에서 정해집니다. 7B는 이 인자를 넣기 전인 commit `47e0f8b`의 스크립트로 실행했습니다(protocol의 harness 해시가 그 시점 파일과 같습니다). 양자화 실험은 `scripts/launch_quant_eval.sh`(작업 형식 `model:precision:dataset:shard:num_shards:gpu`)로 실행했습니다. 깊이는 `scripts/launch_depth.sh`로 만들었습니다.
